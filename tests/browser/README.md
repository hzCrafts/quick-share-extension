# 媒体布局浏览器回归

## 评论分享功能链路

`pnpm test:reply-share` 专门验证评论带主帖功能。用例从适配器注入的真实分享按钮开始，连接生产 `XAdapter → App → ShareModal → ShareCard → exporter`，不预先拼装 `contextThread`，也不替换提取器、弹窗或 PNG 导出函数。

每个场景都经过三个主题的弹窗、预览 PNG、自动复制 PNG、手动复制 PNG、Escape 关闭。覆盖普通主帖、主帖带引用（引用时间有／无链接）、主帖被虚拟滚动移出、评论自己带引用；反例包括二级回复、分享主帖自身、首页无关帖子，以及导航后清除旧主帖缓存。测试只替换外部边界：存储偏好、系统剪贴板接收端和网络图片；不会写入用户剪贴板。浏览器运行于隔离配置，不验证已安装扩展的 WXT 启动／Shadow DOM 注入，也不证明所有线上 X DOM 均已覆盖。

JSON 中按场景记录经过的检查点，PNG 保存到 `.output/reply-share-regression/`。不要把媒体排列矩阵数量当作业务功能覆盖率。

`QS_REPLY_NEGATIVE_CONTROL=1 pnpm test:reply-share` 会仅在测试服务器中恢复旧的“取第一个 time”行为，**预期失败**于 `quoted-root-unlinked-time` 的上下文检查；生产源码不会被改写。该反向验证用于确认用例确实能拦截这次故障，不属于正常发布检查。

GitHub 发布工作流已配置先运行上述链路测试及媒体布局回归，再打包／创建 Release；此变更需要提交推送后才在远端生效。

## 媒体布局矩阵

运行 `pnpm test:media-layout`。需要 Node.js、npx 及 Playwright CLI 可使用的 Chromium/Chrome；命令通过 npx 调用 CLI，首次运行可能需要安装其运行环境。不使用用户已登录的浏览器资料。

该命令自动启动本地 Vite 和独立浏览器，完成后关闭；失败返回非零退出码。JSON 报告与 PNG 保存到 `.output/media-layout-regression/`，不创建新的扩展测试目录。

检查使用生产 ShareCard、X 适配器的原生引用提取和生产 exporter，不调用第三方帖子接口。媒体为离线 SVG，浏览器实际计算布局，不能用 happy-dom 的 DOM 断言代替这些几何检查。

覆盖范围：

- 2、3、4 个附件的全部图片／视频排列；5、6、9 个媒体的全图片、全视频及单视频位置等代表组合。
- 横横、竖竖、横竖、竖横、方形、超宽／超高比例；缺失、零、负数和非有限比例；视频数据更新后的布局切换。
- 三个主题，主帖、原生引用、评论引用，主帖与引用同时带媒体，以及窄预览。
- 校验顺序、格子填充、行列位置、重叠、越界、视频按钮中心、双视频等高比例；调用 exporter 做 640px × 2.5 倍真实 PNG 导出。
- 没有有效页面展示尺寸时保留来源比例；X 依然每行最多两张，最后一张居左并保持单列宽度。
- X 页面展示比例优先于原图和视频实际比例；覆盖三个主题及主帖、原生引用、评论引用中 1–4 个附件的图片／视频全部排列，校验每行最多两张、裁切比例、媒体顺序、视频按钮位置，并抽样实际导出。适配器另覆盖横图／竖图／未加载图片、轮播视口外的完整框、混合媒体及无效展示尺寸。
- 三个主题的纯图片帖子，校验空正文容器不存在、作者栏到附件仅留 12px，并进行实际 PNG 导出；组件测试另覆盖空白富文本、正文切换、内嵌图片、标题、Prompt 及摘录。
- 评论引用一个自身带原生引用的主帖：从详情页 DOM 经过真实适配器提取、组件渲染并导出三个主题，验证主帖身份／日期、评论附图顺序以及主帖内的引用内容。单元测试另覆盖主帖被滚动移出、引用时间有链接／无链接、评论自身带引用等边界。

这是可枚举布局规则的回归，不代表所有真实网站 DOM、所有浏览器版本或网络图片加载失败场景均已覆盖。实际网页的提取问题仍须用相应 DOM fixture 补测。
